# SNR基盤採用監査

**監査日時:** 2026-08-20 JST  
**参照元:** SuperNewRoles `713c98779e14000479f7578a28705264645f07e5`  
**参照URL:** <https://github.com/SuperNewRoles/SuperNewRoles/tree/713c98779e14000479f7578a28705264645f07e5>  
**対象ゲーム参照DLL:** Among Us Steam build `24302054`、Unity `2022.3.44f1`、32-bit IL2CPP

## 結論

SuperNewRoles（SNR）は、tempMODを作り直す際の**役職・設定・会議・カスタムRPCの主参照基盤として技術的に採用可能**です。固定参照コミットは`net6.0`を対象にBepInEx IL2CPP向けプラグインを構築するプロジェクトであり、現行のAmong Us参照DLLを指定した監査ビルドは.NET 8 SDKで**エラー0件**となりました。[1]

ただし、SNR本体をそのままtempMODへコピーして有効化することは行いません。SNRのエントリポイントには、役職基盤以外にも独自サーバ、外部API、ゲーム内リクエスト、告知、カスタムコスメ、独自更新、CPUアフィニティなどの初期化が含まれます。接続の安定性を最優先するtempMODでは、これらを持ち込まず、SNRの役職基盤だけを段階的に採用します。[1]

## SNRから採用する基盤

| 領域 | 採用方針 |
|---|---|
| 役職モデル・役職管理 | SNRの`CustomRoleManager`、役職基底クラス、Ability構成を主参照にします。 |
| 役職設定 | SNRのCustom Option基盤を主参照にします。tempMOD名・日本語表示へ置換します。 |
| 会議処理 | SNRの会議能力・投票・会議終了の状態遷移を主参照にします。 |
| 同期 | SNRのCustom RPC設計を主参照にし、ホスト権限・入力検証・バージョン整合を維持します。 |
| 役職UI | SNRの役職表示・ボタン・設定UI構成を主参照にします。 |
| 役職追加手順 | 役職単位で、参照元・設定・同期・会議・勝利・受入テストをそろえて追加します。 |

## SNRから持ち込まない機能

| 機能群 | 採用しない理由 |
|---|---|
| 独自サーバ・地域更新・マッチメイキング | tempMODの接続経路を変更せず、ネットワーク障害の切り分けを単純に保つためです。 |
| 解析・外部API・ゲーム内リクエスト | ユーザーの明示的な要望がなく、役職MODの最小基盤に不要なためです。 |
| 告知・画像デコーダ・独自更新 | tempMODのGitHub Releases自動更新だけを維持し、外部通信経路を増やさないためです。 |
| カスタムコスメ・トロフィー・実績 | 役職基盤と独立しており、初期安定化の対象外のためです。 |
| CPUアフィニティ変更 | ユーザー端末のプロセス設定を改変しないためです。 |
| プレイヤー複製、テストダミー、ネットワーク参加者追加 | オンライン接続を破壊する危険があるためです。`GameData.AddDummy`、`AmongUsClient.Spawn`、`PlayerControl`複製は引き続き禁止です。 |

## 次の実装方針

1. tempMOD側にSNRをそのまま丸ごと配置せず、SNRのライセンス表示と完全な参照記録を追加します。
2. SNRエントリポイントから外部通信・独自サーバ・コスメ・実績・CPU設定を除外した**最小ローダー**を作ります。
3. SNRの役職マネージャー、設定、同期、会議の依存関係を解決し、役職が未選択でも起動する最小版を作ります。
4. 起動・ロビー・設定画面・会議開始／終了・オンライン入退室を検証してから、シェリフなどの役職を1つずつ有効化します。
