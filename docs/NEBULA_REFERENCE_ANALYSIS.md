# Nebula風設定画面の実装基準

ユーザー提供の参考動画から、設定画面は左から右へ「大分類」「役職選択」「選択役職の具体的設定」を絞り込む三段構成であることを確認した。左カラムは大分類を直接クリックする縦並びの選択肢、中央カラムは選択された陣営の役職リスト、右カラムは有効化・人数・出現率と役職固有の詳細設定である。

数値設定は値を中央に置き、左右に明確な白い「－」「＋」ボタンを置く。ON/OFFは読めるサイズの明示的な切替表示にする。各カラムは固定位置・固定倍率とし、設定項目が多い右カラムのみ必要に応じて標準スクロールで閲覧できるようにする。独自にテキストを拡大したり、標準UI部品の子要素を重ねたりして当たり判定と視覚表示をずらしてはならない。

実機の前回画面では、標準コンポーネントを不適切に拡大・複製したため、左役職リストと右設定が重なり、ボタンの可読性が失われた。以後の固定カラム版ではStringOption行をそのまま一列単位で複製し、行の位置だけを指定する。

## 実ファイルの公開構造から得た追加方針

Nebula本体の公開型情報では、設定画面は標準の設定行を横方向へ無理に並べたものではなく、専用の設定メニューと、陣営タブ・第一ページ・第二ページを分けた複数ページの構成として実装されていることを確認した。tempMODではNebulaのコード・素材・名称を用いず、同じ原則だけを独自に適用する。

次の実装では、標準のゲーム設定枠および標準の設定行をそのまま使う。左側には既存のゲーム設定ボタンと同寸法の「クルー」「インポスター」「第三陣営」ボタンを配置する。中央／右を一画面で無理に併設せず、役職一覧ページから選択役職の設定ページへ遷移する二段階式にする。これにより、文字・矢印・当たり判定・スクロールのすべてがバニラUIの座標系に従い、重なりを防止できる。
