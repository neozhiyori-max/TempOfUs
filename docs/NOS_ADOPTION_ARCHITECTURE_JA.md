# tempMOD：NOS主基盤への段階移行設計

## 結論

tempMODは、公式Nebula配布物のバイナリをそのまま改変するのではなく、GPL-3.0で公開されたNOS Remakeソースを**参照・移植元**として扱う。現行Among Us環境で安全に動くことを確認するまで、実機には導入しない。

## 採用する要素

| 層 | 採用範囲 | 理由 |
| --- | --- | --- |
| 設定UI | NOS型の上部カテゴリ、役職一覧、役職詳細の導線 | ユーザーが求める既存の操作性を維持するため |
| 役職モデル | 役職・オプション・能力ボタン・会議処理の分離パターン | 役職を5件ずつ安全に追加するため |
| 同期 | ホスト権限と専用RPCの構造 | 将来のマルチプレイヤー同期の土台として利用するため |
| UI資産 | 出所と利用条件を確認できるものだけ | 不明瞭な画像資産を無差別に混在させないため |

## 最小ローダーで除外する要素

| 除外対象 | 理由 |
| --- | --- |
| CPUAffinityEditorの生成・実行 | ゲーム外の実行ファイルを生成しない |
| 独自リージョン・サーバー・告知取得 | 接続安定性を優先し、外部通信を持ち込まない |
| `Harmony.PatchAll()` | 未監査パッチを一括有効化しない |
| 全役職・全修飾子・全ゴーストのロード | 最初は役職なしで起動し、5役職単位で有効化する |
| 全RPCロード | 試験済み役職に必要な同期だけを導入する |
| バン状態の強制変更 | アカウント・接続状態へ影響する行為を行わない |
| コスメ、マップ編集、テクスチャパック | 役職基盤の検証に不要であり、資産・互換性リスクを増やす |

## 実装順

1. `TempMod.NosBase` を独立プロジェクトとして作成し、NOS Remakeから最小起動に必要なソースだけを段階コピーする。
2. 現行Among Us参照DLLへのビルドエラーを、コンパイラ、BepInEx、ゲームAPIの3種類に分けて解消する。
3. 役職なし・外部機能なしで、タイトル、ロビー、設定画面の起動を確認する。
4. NOS型設定UIを有効化し、最初のインポスター5役職だけを表示対象にする。
5. 各役職について、設定、抽選、HUD、能力、会議、同期、勝利条件をまとめて完成させる。

## 完了条件

最小NOSローダーは、公開版・管理者検証版の両方でビルドでき、Among Usのタイトル・ロビー・会議・終了まで例外なく到達すること。加えて、禁止された参加者追加、ダミー生成、プレイヤー複製、バン状態変更、外部サーバー初期化、未監査Harmony一括適用を含まないこと。
