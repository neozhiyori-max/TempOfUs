# tempMOD：公式NOS上のアドオン方式への移行設計

## 結論

tempMODは、公式Nebula on the Ship（NOS）本体を改変・再配布するのではなく、**公式NOS配布版の上で読み込まれる独立アドオン**として実装する。NOS本体が提供する上部メニュー、設定画面、役職一覧、詳細画面、同期基盤の動作には手を加えない。

この方式では、ユーザーが気に入ったNOSの画面構造・操作感をそのまま維持し、tempMODは独自役職、独自設定、独自の説明文、必要最小限の同期だけを担当する。

## 参照対象と役割

| 対象 | 役割 | tempMODでの扱い |
| --- | --- | --- |
| 公式Nebula配布版 | 現行版対応のNOS本体、UI、役職・同期ランタイム | **無改変。配布元の導入手順に従って利用。** |
| 公式NebulaLoader | NOS本体のロード | **無改変。** |
| 公開NOS Remakeソース（GPL-3.0） | API形状、アドオン構造、役職実装の参照 | tempMOD独自コードの設計・移植元として参照。派生コードはGPL-3.0条件を守る。 |
| tempMODアドオン | tempMOD独自役職、設定、説明、同期 | 新規作成し、NOS本体とは別DLLとして配布する。 |

## 安全境界

tempMODアドオンは、公式NOS本体の以下の機能を置き換えず、呼び出さない。

| 禁止・非採用項目 | 理由 |
| --- | --- |
| NOS本体DLL、NOS Loader、BepInExコアの改変 | 公式本体の安定UI・同期を壊さないため |
| CPUAffinityEditorなどゲーム外実行ファイルの生成 | tempMODの役職機能に不要なため |
| 独自リージョン・サーバー・告知取得 | 接続安定性を優先し、外部通信を増やさないため |
| バン状態の変更・無効化 | アカウント・接続状態に関与しないため |
| プレイヤー複製、ダミー生成、参加者追加 | 過去のWi-Fi切断・再接続制限の再発を防ぐため |
| 未監査のHarmony全パッチ | 競合する改変を一括適用しないため |

## 実装順

1. 公式NOS配布版を隔離環境で起動確認し、現行Among Us版・BepInEx版との整合を確認する。
2. `TempMod.NosAddon.dll` を作成し、NOSが存在する場合だけ読み込まれる**役職なし最小アドオン**として起動確認する。
3. NOSのアドオンAPI・設定登録・同期経路を、公開Remakeソースと実機ログで照合する。
4. 最初のインポスター5役職を、設定・抽選・HUD・能力・会議・同期・勝利条件まで1セットとして実装する。
5. 各5役職セットごとにビルド、安全監査、実機確認、GitHub反映を完了する。

## 完了条件

最小アドオンは、公式NOS本体と同居した状態でAmong Usのタイトル・ロビー・設定画面・会議・終了まで例外なく動作すること。さらに、tempMODアドオンを外せば公式NOSだけで元どおり起動できることを確認する。
